## Appendix A: Phase 2 "Dead End" Audit

Five experiments from Phase 2 were labeled dead ends. On closer inspection, two are genuine negative results, one is a methodology flaw, and two are confounded by the same root cause.

### 1. Jacobian Variance (cycle 009) — Genuine negative

**What it measured:** A linearity index L = 1 - mean(||J(x) - J̄||_F / ||J̄||_F) per FFN block, where J(x) = W_out @ diag(σ'(z)) @ W_in is the per-token Jacobian. L≈1 means the block is nearly affine (Jacobian barely varies across tokens). L≈0 or negative means each token sees a substantially different local linear map.

**Result:** Max L = 0.38 (block 1). 8/12 blocks have negative L — per-token Jacobian deviation exceeds the mean Jacobian norm. The block function is genuinely token-dependent.

**Assessment:** Methodology is sound (efficient factored computation, 256 tokens, Frobenius norm). The result is informative: GPT-2 FFN blocks are genuinely nonlinear and cannot be approximated by a single affine map. This correctly ruled out single-affine collapse and motivated multi-region approaches.

**Status: Legitimate dead end.** Single-affine compression is not viable for GPT-2 FFN.

### 2. Manifold Curvature (cycle 020) — Methodology flaw (LayerNorm confound)

**What it measured:** Local manifold curvature via k-NN (k=50) + local PCA. For each token, find 50 nearest neighbors, fit PCA, define curvature as the fraction of variance not explained by the top-d principal components (where d is chosen to explain ≥95%). Averaged across 512 tokens at each of 13 layer boundaries.

**Result:** 0.045-0.047 across all 13 layers — essentially constant. Spearman rho = -0.42 (p=0.17, not significant).

**Why this is wrong:** Every transformer block ends with LayerNorm, which normalizes representations to zero mean and unit variance. This erases local curvature signatures — all layers "look the same" in variance structure after normalization. The metric measures the geometry of LayerNorm's output distribution, not the geometry of the computation.

**What would fix it:** Hook before LayerNorm (pre-norm activations), or use a curvature metric invariant to affine rescaling. Pre-LayerNorm representations carry the actual geometric structure; post-LayerNorm representations are homogenized by design.

**Status: Methodology flaw, not a dead end.** The hypothesis (curvature varies across layers and predicts compression difficulty) was never actually tested. Should be reclassified as inconclusive (confounded).

### 3. Intrinsic Dimension (cycle 015) — Confounded (same LayerNorm issue + more)

**What it measured:** TwoNN MLE estimator (Facco et al. 2017) on token representations at each layer boundary. The estimator uses the ratio of 2nd to 1st nearest-neighbor distances to estimate the intrinsic dimension of the data manifold. Applied to 4128 tokens (32 sequences × 128 tokens) flattened as independent samples in 768 dimensions.

**Result:** ID rises monotonically 1.64 → 7.46 through depth. Spearman rho = -0.16 (p=0.62) with compression damage.

**Problems:**
- **LayerNorm confound** (same as curvature): post-norm representations have homogenized variance structure
- **Independence assumption violated**: 4128 tokens treated as i.i.d. but strongly correlated within sequences
- **Low N/D ratio**: 4128 samples in 768 dimensions (N ≈ 5.4D) — TwoNN accuracy degrades here
- **No null baseline**: what TwoNN gives on random Gaussian in 768d was never established
- **Measures the wrong thing**: TwoNN estimates the dimension of the *representation cloud* (how many dimensions tokens spread across), not the *functional rank* of the FFN map (how many independent output directions the FFN uses). These are different quantities — the representation could live on a high-dimensional manifold while the FFN's actual function is low-rank.

**Status: Confounded.** The rising ID trajectory (representations become more complex through depth) may be real but the confounds make the absolute values and the correlation with compression damage unreliable. Shares the LayerNorm root cause with curvature.

### 4. RTG Spectral Coarsening (cycles 013-014) — Genuine negative

**What RTG is:** A ReLU network partitions its input space into polyhedral regions, each defined by a binary activation pattern (which neurons are on/off). Within each region, the network computes a fixed affine map A_ω·x + b_ω (this is the MASO/SplineCam framework). The **Regional Topology Graph (RTG)** is a graph where:
- **Nodes** = observed activation patterns (one per distinct binary mask seen in the data)
- **Edges** = Hamming distance 1 (two patterns connected if they differ by exactly one neuron flip)

This captures which linear regions are *geometrically adjacent* in input space — if you cross one hyperplane (one neuron switches on/off), you move from one region to a Hamming-1 neighbor. The hypothesis: neighboring regions should have similar affine maps, so spectral clustering on the RTG should find groups of regions that can be merged into coarser approximations.

**Cycle 013 (toy ReLU):** Built the RTG for a 2→32→32→1 network trained on 2D spirals. Found 330 unique patterns forming a graph with **79 disconnected components**, mean degree 1.7, 11% isolated nodes. The graph is too sparse — most patterns have no Hamming-1 neighbor because in 64-dimensional binary space, two random binary vectors almost never differ by exactly 1 bit. Spectral clustering on this fragmented graph beats random by 9.4pp (proving the structure is real) but max accuracy is only 60% vs 95.5% float. The fragmentation prevents useful compression.

**Cycle 014 (GPT-2):** To avoid the sparsity problem, switched from Hamming-1 adjacency to k-NN (k=10) on per-token Jacobian matrices (768×768, computed analytically). This gives a connected graph. Spectral clustering on this graph vs plain k-means on the same Jacobians. Result: spectral at parity with k-means across all blocks and K values (max improvement 1.3%, threshold was 15%).

**Why spectral adds nothing:** The Jacobian space is continuous and Euclidean. k-means already captures the density structure. The graph Laplacian eigenvectors on a k-NN graph in a smooth space reduce to a kernel density estimate — equivalent to what k-means does. There are no topological bottlenecks or nonlinear manifold structure for spectral methods to exploit.

**Status: Legitimate dead end.** Two well-designed experiments confirming that activation/Jacobian space lacks the topological structure spectral methods need. The Hamming-1 RTG is too sparse for practical networks; the k-NN proxy is no better than Euclidean clustering.

### 5. Local-Chart Compression (cycle 029) — Genuine negative, with implications

**What it did:** Replaced global top-384 channel selection with a mixture-of-experts approach: k-means clusters the FFN inputs into K regions (K=4 or K=8), each region gets its own top-(384/K) channel set and its own lstsq-fitted W_down. At inference, each token is routed to its nearest centroid's specialized compression. Total budget is matched: K charts × (384/K channels) = 384 channels.

**Result:** Local-chart is worse in all 6 comparisons (3 blocks × 2 K values). Block MSE increases 40-70%. The capacity cut per chart (each gets only 96 or 48 channels) cannot be compensated by specialization.

**Key finding: GELU FFN blocks are globally low-rank, not locally specialized.** The important channels are important for ALL tokens, not region-specific subsets. Input-space partitioning doesn't create meaningful functional subgroups — the FFN's dominant output directions are shared across the entire input domain.

**Implications for compression and intrinsic dimension:**

This result, combined with the per-block compression results (6-10x works, meaning ~300-500 of 3072 channels carry most of the signal), tells us something fundamental: **each FFN block's function is effectively a global low-rank map with rank ~300-500.** The topk+lstsq pipeline is already finding this low-rank structure by selecting the globally most active channels.

This reframes the intrinsic dimension question. Cycle 015 tried to measure ID of the *representation cloud* (how many dimensions the token vectors span). But the operationally relevant quantity for compression is the **effective functional rank**: how many independent output directions does the FFN's Jacobian actually use? If the FFN map is globally low-rank, its Jacobian J(x) = W_out @ diag(σ'(z)) @ W_in should have consistently low effective rank across tokens — and that rank is the theoretical compression limit.

This suggests a concrete follow-up: **measure the effective rank of the FFN Jacobian directly** (SVD of J(x) for a sample of tokens, compute rank at 95% and 99% energy thresholds). If rank is consistently ~300-500, that confirms the compression ceiling and explains why 6-10x works. If rank varies substantially across tokens, it explains why some blocks are harder (those with higher effective rank need more channels). This would also connect to the P1 Frobenius std oracle (cycle 048): blocks with higher Jacobian variance may have higher effective rank, requiring more channels.

**Status: Legitimate dead end for local-chart MoE, but the "globally low-rank" finding is load-bearing.** It explains why topk works, predicts the compression limit, and points toward functional-rank measurement as the right intrinsic dimensionality concept for this problem.
