learned=Centroid-based topk channel selection is data-hungry, not data-efficient. Jaccard stability grows monotonically with probe size but requires >2048 tokens to approach 0.85. Even at 2048 tokens, 3-way Jaccard is only 0.844, revealing inherent inter-seed variability in the scoring function. A secondary concrete hazard: lstsq output-projection refit is numerically unstable when probe_tokens approximately equals hidden_dim (e.g., 512 tokens, k=512 channels), causing PPL to explode. This is an implementation hazard for any deployment that caps probe size near k.
next=Since channel selection is unstable at small probe sizes, the natural question is whether a data-free (weight-only) channel scoring can match or exceed the data-conditioned score at any probe size. The channel_scores formula uses std_hidden * output_norms * (mean_hidden + mean_deriv), which is data-conditioned. A weight-only baseline (score = output_norms alone, or weight_norm_in * weight_norm_out) would test whether data conditioning adds value. If weight-only scores produce comparable Jaccard, the probe corpus can be eliminated entirely. This would be item 82 (spectral vs topk) or a new item testing data-free vs data-conditioned channel selection.
