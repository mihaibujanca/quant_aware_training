## Methodology check
- **Calib slice**: 256 tokens = first 2 sequences × 128 tokens of the standard cycle 218 / 258 / 259 wikitext-2 val loader with seed 42 and SEQ_LEN=128. Sequence count derived deterministically via `n_seqs_needed = (N_TARGET_TOKENS + SEQ_LEN - 1) // SEQ_LEN = 2`. The script slices the first 256 tokens of the concatenated c_fc-input stash so the token sampling matches the brief's "256 calib tokens from the calib slice". PASS.
- **c_fc input hook**: `make_cfc_hook(l)` registers a `forward_hook` on `model.transformer.h[l].mlp.c_fc` and captures `input[0].detach().float().cpu()` — byte-identical to cycle 218 `make_cfc_hook` (line 67-69) and cycle 258's pattern. 12 hooks, all removed after the single forward pass. PASS.
- **HF Conv1D layout**: `W_fc = c_fc.weight` shape (768, 3072), `b_fc` shape (3072,), `W_proj = c_proj.weight` shape (3072, 768). All asserted in `W_fc_per_block` / `W_proj_per_block` construction. `preact = ln2_out @ W_fc + b_fc` — matches cycle 218 line 138 exactly. PASS.
- **σ'_GELU via fresh-leaf autograd**: `z = preact.detach().clone().requires_grad_(True); y = F.gelu(z, approximate='tanh').sum(); sigma_gelu_prime = torch.autograd.grad(y, z)[0].detach()`. This is the correct pattern because the `preact` tensor is not a leaf (it's produced by matmul from frozen weights). The fresh clone creates a new leaf, the sum reduces to a scalar for backward, and `torch.autograd.grad` returns the element-wise derivative. Shape (256, 3072) correct. PASS.
- **σ'_ReLU via strict > 0**: `sigma_relu_prime = (preact > 0).float()` — matches brief's "σ'_ReLU = (z > 0).float()". At z = 0 exactly, ReLU'(0) = 0 and GELU'(0) = 0.5 so delta_diag[z=0] = +0.5, consistent with the observed elementwise bound delta_diag ∈ [−0.5, +0.5]. PASS.
- **delta_diag bounds sanity**: the script reports delta_diag stats per block — all blocks show min=−0.500, max=+0.500, which is the analytic bound `|GELU'(z) − ReLU'(z)| ≤ 0.5` (GELU' ∈ [−0.13, ~1] and ReLU' ∈ {0, 1}, with the 0.5 bound at z=0). PASS.
- **ΔJ construction**: per token t, `DJ_t = (W_proj.T * delta_diag[t].unsqueeze(0)) @ W_fc.T` = (768, 3072) * (1, 3072) broadcast → (768, 3072) @ (3072, 768) = (768, 768). Shape correctness asserted. The formula matches the brief: `ΔJ = W_down.T @ diag(delta_diag) @ W_up` where `W_down = c_proj.weight` (3072, 768) so `W_down.T` is (768, 3072), and `W_up = c_fc.weight` (768, 3072) so `W_up.T` is (3072, 768). Elementwise multiplication with `delta_diag.unsqueeze(0)` broadcasts across the (768,) dim 0 of `W_proj.T`, scaling each column by its `delta_diag[c]` factor — equivalent to right-multiplying by `diag(delta_diag)`. PASS.
- **Per-token rank_95**: `sv = torch.linalg.svdvals(DJ_t)` returns only singular values (no U/V), much cheaper than full SVD. `energy = sv*sv`, `cum = energy.cumsum(0) / energy.sum()`, `r95 = int((cum < 0.95).sum().item()) + 1` — matches cycle 218 line 153 convention exactly. PASS.
- **DJ_avg running sum**: `dj_sum.add_(DJ_t)` inside the per-token loop, then `dj_avg = dj_sum / N_TARGET_TOKENS`. Memory efficient (one (768, 768) accumulator instead of 256 × (768, 768) = 604 MB). PASS.
- **Mode-1 subspace (average-then-SVD)**: `U_avg, S_avg, _ = torch.linalg.svd(dj_avg, full_matrices=False); U_top20 = U_avg[:, :20]`. This is the primary mode-1 aggregation path from the plan. The "averaged ΔJ over tokens, SVD, top-20 left SVs" approach matches the brief's "simpler" option. The stack-mode-1 secondary diagnostic was dropped but was not required. PASS (primary path executed as planned).
- **c_fc reader basis of block l+1**: `top_left_svs(W_fc_per_block[lp1], 20)` matches cycle 218 line 216's pattern — top-20 left singular vectors as columns (768, 20). Built for lp1 ∈ {1..11}. PASS.
- **Principal cosine computation**: `M = U_top20.T @ B_reader` (20, 20), `cos = torch.linalg.svdvals(M)` (20,) descending, `top5_sum = cos[:5].sum()`. This is the standard "principal cosines between two 20-D subspaces of R^768" computation (cycle 218 line 309 uses `V20 @ B` where V20 is (20, 768) and B is (768, 20) → same quantity). PASS.

## Hypothesis vs result
- **Hypothesis**: per-token median rank_95(ΔJ_l) ≤ 100 in ≥6 blocks (low-D operator) AND mode-1 subspace aligns with c_fc reader of block l+1 at top-5 cos sum ≥ 2.0 in ≥6 blocks.
- **Reality**:
  - Low-D operator clause: **FAILS**. Median rank_95 plateaus at ~335/768 across all 12 blocks (minimum 332, block 1 outlier at 407). The brief's "concentrated near z = 0" reasoning about σ'_GELU − σ'_ReLU is correct pointwise, but the aggregation across 3072 channels spreads the disagreement to 60-74% of channels. The brief specifically flagged "rank tells us how many channels are in the disagreement zone as operators, not just as outputs" — and the answer is ~335, which is a lot more than cycle 217's zeroth-order rank_95 ≤ 64. The zeroth-order and first-order ranks are structurally different because the output ΔJ @ x is a linear combination of channels weighted by (GELU(z) − ReLU(z)), which is sparser than (GELU'(z) − ReLU'(z)).
  - Alignment clause: **PASSES STRONGLY**. 10/11 pairs clear the 2.0 threshold (only 10→11 at 1.926), and all 11 pairs clear 3σ significance vs random (1.2557 ± 0.0448). Peak 3.487 at pair 5→6 is stronger than cycle 218's zeroth-order centred Δ̃ top-5 ~2.97 — the operator-level alignment is tighter than the output-level alignment.
- **Verdict INCONCLUSIVE is correct**: the two clauses give opposing answers, so neither CONFIRMED nor REFUTED is triggered. The brief explicitly allows this outcome ("INCONCLUSIVE between — partial signal, decide on a focused per-block follow-up").
- **Geometric reading**: the operator ΔJ_l is NOT low-dimensional (medium-rank ~335/768) BUT its DOMINANT DIRECTIONS (top-20 left SVs of the averaged operator) are precisely targeted at the next block's c_fc reader. Rank and alignment are separable properties of the operator — the brief conflated them under a single "low-dimensional, structurally targeted" label. The cycle 218 "bump writes into next block's c_fc reader" finding at the zeroth order (output Δ̃) survives AND strengthens at the operator level (ΔJ), but the "because it's low-rank" half of the intuition is wrong.
- **Counterintuitive check** (CLAUDE.md rule): the "medium-rank but strongly aligned" result is counterintuitive given the brief's expectation. Three sanity checks support it: (a) delta_diag bounds ∈ [−0.5, +0.5] match the analytic z=0 bound; (b) random baseline reproduces cycle 218's 1.27; (c) the alignment pattern has a clean middle-block peak matching cycle 258's κ-load localization. No measurement bug found. The finding is robust.
